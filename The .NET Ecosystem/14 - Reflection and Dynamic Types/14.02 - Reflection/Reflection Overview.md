## What Is Reflection?

**Reflection** is the process of runtime type discovery — programmatically inspecting and interacting with metadata at runtime. It gives you the same information that `ildasm.exe` shows, but through a friendly object model in code.

## How Reflection Works Under the Hood

Reflection reads the **metadata tables** embedded in every .NET assembly. These tables (`TypeDef`, `MethodDef`, `FieldDef`, etc.) are generated by the compiler and baked into the PE file. Reflection doesn't scan source code or PDB files — it reads structured binary metadata.

```
Your C# code                          At Runtime
    |                                      |
    v                                      v
Compiler generates:                   CLR loads assembly into memory
+------------------+                  +------------------+
| IL Code          |                  | IL Code -> JIT   |
| Metadata tables  |<--------------->| Metadata <-- Reflection reads THIS
|  - TypeDef       |                  |                  |
|  - MethodDef     |                  | typeof(Person)   |
|  - FieldDef      |                  |   .GetMethods()  |
|  - Attributes    |                  |   .GetFields()   |
| Manifest         |                  |                  |
+------------------+                  +------------------+
```

## The System.Reflection Namespace

Key types in `System.Reflection`:

| Type | What It Describes |
| --- | --- |
| `Type` | A type (class, struct, enum, interface, delegate) |
| `MethodInfo` | A method |
| `PropertyInfo` | A property |
| `FieldInfo` | A field |
| `ConstructorInfo` | A constructor |
| `EventInfo` | An event |
| `ParameterInfo` | A method parameter |
| `Assembly` | An assembly |
| `Module` | A module within an assembly |

All of these inherit from `MemberInfo` (except `Assembly` and `Module`).

## Common Use Cases

- **Plugin/extension systems** — load and instantiate types from external DLLs at runtime
- **Serialization/deserialization** frameworks (JSON, XML)
- **Dependency injection containers** — resolve types by interface
- **ORM frameworks** — map types to database tables
- **Unit testing frameworks** — discover and run test methods
- **IDE features** — IntelliSense, refactoring, code analysis

```ad-warning
title: Performance and Safety Tradeoffs
Reflection is powerful but comes with costs: it's **slower** than direct calls (no JIT optimization, boxing, security checks), it **bypasses encapsulation** (can access private members), and it **breaks at runtime** rather than compile time. Use it when you genuinely need runtime type discovery — not as a substitute for good design.
```
